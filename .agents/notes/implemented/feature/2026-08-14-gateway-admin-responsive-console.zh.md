# Agent Note: 响应式 Gateway 管理控制台

Status: implemented

[English](2026-08-14-gateway-admin-responsive-console.md) | 中文

## 问题

Gateway 管理 SPA 虽然提供了完整的管理操作，却只是若干没有结构的标题、原生控件和宽表格。桌面布局没有建立导航和层级；同一套表格在手机宽度下也难以浏览和操作。变更操作缺少统一的加载、错误、确认和焦点模型，因此各页面可能逐渐偏离，而底层管理 API 保持不变。

## 决策

`gateway/admin-ui` 维护一套小型共享表现层（`PageHeader`、`Section`、`Button`、`IconButton`、`StatusBadge`、`Field`、`Dialog`、`ConfirmDialog`、`LoadingState`、`EmptyState` 和 `ErrorBanner`），并在 `index.css` 中维护统一的视觉变量。用户、项目、模型、用量和审计页面通过这些原语使用相同的层级、状态色、表单间距、键盘焦点和异步状态。导航和紧凑操作使用 Lucide 图标；仅图标控件带有可访问名称和悬停提示。

桌面视口使用固定 `224px` 侧栏和受约束的内容列。视口宽度不超过 `840px` 时切换为吸顶品牌栏和五项固定底部导航，每个数据表同时提供保留相同字段与操作的移动卡片表示。宽度不超过 `560px` 时，表单网格改为单列，操作组填满可用宽度，弹窗接近视口大小并让正文独立滚动。粗指针控件预留 `44px` 触控目标。样式遵循深色配色和减少动画偏好，并通过底部导航和安全区内边距避免遮挡内容。

页面行为仍由 API 驱动：加载、空状态和错误状态明确呈现；破坏性操作使用确认弹窗；创建和编辑表单只在请求成功后关闭；模型、额度、成员、实例、审计筛选和分页控件保留其 API 语义。项目详情把成员与运行时操作同项目自然月用量组合起来，并复用共享 `UsageSummaryView`；额度弹窗在管理员明确选择继承普通成员额度或项目独立额度前保持禁用，独立模式会同时提交 token 与公司成本字段。项目目录验证会把宿主机文件系统失败转换为稳定的 API 诊断，创建弹窗翻译这些诊断时不会丢弃已输入的名称或路径。Vite 构建将静态资源写入 `gateway/public/admin`，由网关直接提供。

## 考虑过的替代方案

**保留原生控件和宽表格。** 否决：现有 API 并不要求桌面专用展示，宽表格会在手机上迫使用户横向滚动或让操作被裁切。

**复用主 Web 应用的 shell 包。** 否决：Gateway 管理端是独立 Vite SPA，使用单独的部署产物，不运行 Cordis 客户端插件；本地原语层既保持构建独立，也能遵循产品现有的克制视觉语言。

**移动端只使用汉堡抽屉。** 否决：固定五项底部导航让五个管理区域始终一键可达，并在不增加覆盖层状态的情况下保留当前页面上下文。

**只保留一份 DOM 表格并压缩列宽。** 否决：压缩列会隐藏路径、状态和操作标签；独立移动卡片能保留可读的字段/值分组，并明确触控操作。

## 后果

桌面用户获得稳定导航和更适合比较的密集视图，手机用户获得单列流程、触控尺寸控件和无横向溢出的页面。移动卡片与桌面表格存在两套展示标记，因此每次管理行变更都必须同步两条渲染路径；共享行数据和针对性的浏览器检查保持它们一致。全局与项目页面共用一份用量汇总展示组件，而各页面自行拥有筛选与变更控件。静态资源部署是构建步骤，不是数据库或会话迁移；运行中的网关可以在不重启活跃个人或项目运行时的情况下提供新 bundle。

## 测试

管理端 Vitest 覆盖导航、API 请求约定、用户确认与创建流程、项目路径失败、项目用量/月份选择、显式额度来源提交以及共享应用渲染。Gateway 测试固定路径不存在时的稳定诊断和项目额度语义。TypeScript 和 Vite 构建通过。带认证的生产浏览器检查在 `1440x900` 和 `390x844` 下覆盖五个路由及项目详情，验证侧栏/底部导航模式，确认 `scrollWidth` 不超过视口，并截取页面进行视觉复核。
