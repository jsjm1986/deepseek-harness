# @deepseek-ai/dsh-userdoc-local

[English](README.md) | 中文

`userDocs` 的本地后端：把上传内容存成一个配置根目录下的普通文件，默认根目录为 `<home>/uploads`。保存后的路径为 `<root>/<YYYY-MM-DD>/<文件名>`，因此同一天的上传聚在一起，而用户在界面上看到的路径就是 agent 用 `read` 或 `bash` 读取的那个路径。

写入分两步。`resolveTarget` 先净化不受信任的客户端文件名——手动剥除两种分隔符、移除控制字符、按字节截断到 255、拒绝纯点名称——再挑选第一个空闲叶名，冲突时在扩展名之前加 ` (2)` 后缀，超过一千次冲突则以 `DOC_NAME_EXHAUSTED` 失败。`save` 写入同级 `.part` 文件，该文件以 `O_CREAT | O_EXCL` 打开，因此绝不会跟随预先埋设的符号链接；字节在到达时即计数，超限的上传会被中途切断而不是先缓冲下来，随后 fsync 并 rename。任何失败路径都会删除残留的部分文件。包含关系按路径段而非字符串前缀证明，一次在解析目标时，一次在写入前。

读取接受 store 作用域内的 `docId`——即以正斜杠表示的根相对路径——而绝不接受调用方持有的 `UserDocRef.path` 副本。每次读取都从该标识符重新推导路径并重新证明包含关系，因此被篡改的引用无法指向根目录之外的文件。`list` 跳过符号链接而不跟随，并隐藏进行中的 `.part` 文件；根目录不存在时返回空列表。`openRead` 交给下载路由一个流，其描述符在取消时关闭。`remove` 将文件本已不存在视为成功。

`mediaType` 由存储文件的扩展名推导，无法识别的扩展名记为 `application/octet-stream`。它只是展示用的元数据：这里既不解析内容，也不拒绝未知格式。

## 模型体验

该包通过主机的提示装配消费方间接影响模型：消费方把已存储的引用转换为内联文本，或转换为一个由 agent 用常规工具读取的路径。

#### KV 缓存影响

无；该包既不组装也不发送提供方请求。

## 已知限制与待完成工作

- **没有按用户的磁盘配额** — `maxFileBytes` 限制单次上传，`maxMessageBytes` 限制单条消息，但没有任何限制作用于一个根目录的总大小，因此多用户共享磁盘的部署需要在该包之上再加配额。
- **保留策略需手动处理** — 已存储的文档会一直存在，直到用户删除；没有过期机制或垃圾回收。
- **`list` 每次调用都遍历整棵目录树** — 没有索引，因此存有数千个文件的根目录每次列举都要付一次完整扫描的代价。
- **按天分组使用 UTC** — 在本地午夜前后上传的用户会看到文件位于 UTC 日期之下，可能与其日历日期不一致。
