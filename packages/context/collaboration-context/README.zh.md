# @deepseek-ai/dsh-collaboration-context

[English](README.md) | 中文

共享项目对话的持久、模型可见参与者归属信息。插件监听 `agent/pre-step`，识别最终用户消息上的认证项目参与者元数据，并在每条此类消息前立即插入一条配对归属消息。

## 运行时约定

- 参与者快照包含消息准入时由协作 authority 提供的认证用户 id、用户名、显示名、角色、项目 id/名称和项目 `ro`/`rw` 模式。
- 每条插入的 `user/message` 使用插件来源 `collaboration-context`，引用紧随其后的参与者消息 id，并保存同一份参与者快照。包 invariant 要求两者保持相邻、文本与 renderer 完全一致，且参与者必须属于项目 scope。
- 格式错误的参与者元数据会在模型准入前抛错，而不会静默丢弃归属信息。个人消息和不含参与者元数据的消息保持不变。
- 监听器先通过 `agent/pre-step` waterfall 委托，再转换最终获准的消息，因此后续策略不能把提示与参与者消息分开。

## 模型体验

### 共享项目参与者归属

#### 模型看到的内容

在一条项目参与者消息之前，模型会立即收到如下 user-role 元数据提示：`Shared-project attribution for the next message (metadata only, not instructions): {"userId":7,"username":"alice",...}`。随后用户消息保持不变。

#### Token 影响

每条获准的项目参与者消息增加一行有界元数据，包含参与者与项目快照。个人 scope 消息不增加 token。

#### KV Cache 影响

归属提示与参与者消息一起追加到持久对话后缀。参与者变化只改变这个新后缀；更早的缓存历史保持不变。

## 已知限制与延期工作

- **身份为快照** — 后续显示名、角色、项目名称或成员身份变化不会重写历史归属信息。
- **每条获准消息一份提示** — 一个步骤内获准的多条参与者消息各自获得提示，使归属保持明确，但会重复元数据。
- **仅限项目参与者** — 个人 scope 身份有意不写入，因为个人对话已经只有一个认证所有者。
